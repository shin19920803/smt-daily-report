## 原因

## 限制與復原

Supabase 免費 Nano 資源仍有上限；此修正限制維護排程單次占用時間，不能保證平台資源耗盡或外部故障永不再發生。若登入再次逾時，應先查看 DB CPU、Disk IO Balance 與 `cron.job_run_details`，勿停用登入保護或延長全域逾時作為繞過方式。

需要回復排程指令時，依備份 CSV 的 job ID 與原始 command，在確認目標 job 仍是相同維護／清理工作後，使用 `cron.alter_job(jobid, command := 原始command)` 回復；不要刪除排程或改動生產資料。回復會移除本次單次執行期限，應僅用於有明確原因的短暫排錯。
